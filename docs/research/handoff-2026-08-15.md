# Handoff — Eve state and next moves

**Date:** 2026-08-15

## Where we are now

Eve is a runnable root orchestrator agent with a solid tool surface:

- **Model:** `eve-orchestrator` via the Agency Gateway. LiteLLM fallback group tries CF models in deterministic order (YRKA > JAMI; Kimi K2.7-code > Kimi K2.6 > Gemma 4), 256K context window, reasoning enabled.
- **Host access:** `bash`, `read_file`, `write_file`, `glob`, `grep` all run on the host filesystem instead of the sandbox. No Docker Desktop required locally.
- **Web search x4:** `web_search` (Tavily), `exa_search` (Exa), `brave_search` (Brave), `firecrawl_search` (Firecrawl). All live-verified.
- **Media:** `generate_image`, `text_to_speech`, `transcribe_audio` wired through the Agency Gateway (CF Workers AI).
- **Gateway ops:** `check_proxy_health` probes the unified gateway.
- **Identity:** `whoami` returns the current session principal (mostly useful once real auth is in front).

## Recent decisions

1. **Routing lives in the gateway.** The deterministic Cloudflare fallback moved from Eve into the Agency LiteLLM config (`router_settings.fallbacks`). Eve pays no per-step resolver cost.
2. **Local dev = host access.** We override the sandbox-backed shell/file tools to operate directly on the developer machine. This removes the Docker requirement and matches the user's "one happy family" mental model.
3. **Search providers as separate tools.** Each provider gets its own tool so subagents can specialize, rather than hiding everything behind a single `web_search` abstraction.

## Next focus: voice, audio, and the ElevenLabs/video shell

The immediate open question is where voice and audio fit in the stack:

- Keep `text_to_speech` and `transcribe_audio` as-is, or replace/remove them in favor of ElevenLabs?
- How does the ElevenLabs/video agent call into Eve and receive results?
- What is the proven, official pattern for bridging an external voice/avatar layer with an eve agent?

## Proven patterns to investigate (official sources first)

1. **eve channels**
   - Docs: `node_modules/eve/docs/channels/`
   - A channel normalizes inbound transport into eve sessions. ElevenLabs could post webhook events to a custom eve channel, or the browser client that hosts the ElevenLabs conversation could proxy messages to Eve.
   - Look at `defineChannel` and the bundled `chat-sdk` / `slack` channels as reference implementations.

2. **Client SDK / `useEveAgent`**
   - Docs: `node_modules/eve/docs/guides/client/`
   - If the ElevenLabs/video layer runs in a browser, the React/Vue/Svelte client SDK gives a first-class way to start Eve sessions and stream results back.

3. **ElevenLabs Conversational AI / Agents SDK**
   - Official docs and SDK examples should show how to register custom tools/actions that call an external HTTP API.
   - Eve exposes a stable HTTP API at `POST /eve/v1/session` and `GET /eve/v1/session/<id>/stream`. That is the natural seam: ElevenLabs calls Eve, Eve streams back text/tool results.

4. **Remote agent / subagent delegation**
   - Docs: `node_modules/eve/docs/subagents/`
   - Another shape: run Eve as a subagent/remote agent invoked by the ElevenLabs orchestrator. The voice layer owns turn-taking and persona; Eve owns tool use and long-running tasks.

5. **Reference projects on disk**
   - `c:\Users\james\orgs\oss\avatar-agent` — dormant but working avatar agent.
   - `c:\Users\james\projects\gardens` — multi-provider ElevenLabs/Anam setup.
   - These are evidence, not current truth. Inspect them for patterns, then verify against the official docs.
